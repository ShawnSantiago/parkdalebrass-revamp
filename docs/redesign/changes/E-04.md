### 3.1 · Journal items: HTTP link, not BLOG + tags (D-40)

The first call (`jewelry-main-menu`, 02:01Z) returned `userErrors: []`, but Shopify **dropped the tags** on the BLOG item: it was stored as `type: BLOG`, `url: /blogs/news`, `tags: []` (confirmed by a re-read). `MenuItemCreateInput.tags` is documented as "the menu item's tags to filter a collection", so it only applies to COLLECTION items. A BLOG item can't carry a tag filter through the API, and the stored link went to the unfiltered blog (101 legacy smoking articles), which D-36 rules out.

So both Journal items become an **HTTP item with the relative URL `/blogs/news/tagged/journal`**, the same link D-36 asks for (Admin's menu editor stores a typed-in tag URL the same way). Recorded as D-40.

- `jewelry-main-menu`: one `menuUpdate` that resends every item with its ID unchanged and changes only the Journal item (`gid://shopify/MenuItem/833638400322`) to `{ "title": "Journal", "type": "HTTP", "url": "/blogs/news/tagged/journal" }` (no `resourceId`, no tags).
- `footer-learn`: created with the Journal item as `{ "title": "Journal", "type": "HTTP", "url": "/blogs/news/tagged/journal" }` in place of the BLOG item in §3.
- Trade-off: the link no longer follows the blog by resource, so if the `news` blog handle ever changes, update both items. `link.current` and `link.active` still work for an HTTP link (they compare the URL with the request path); the theme doesn't check the Journal item's link type.

## 4 · Rollback

The change is additive, and nothing on the live store reads these menus. Rolling it back fully means **deleting** the five menus, so under D-28 **tell the owner before doing it**.

1. Read the menus: `menus(first: 50)`, selecting `id handle title items { id title }`, and confirm the five IDs in §5.
2. If the new theme is already published, first point its header (`sections/header-group.json`), footer blocks (`sections/footer-group.json`), `templates/collection.json` and `templates/product.json` back at `main-menu` and `footer`, or republish the Craft theme (Phase 5 rollback), so no live section loses its menu.
3. Delete each new menu with `menuDelete(id: <menu id>)`, selecting `deletedMenuId userErrors { field message }`. Delete only the five IDs in §5. **Never delete `main-menu`, `footer` or any other existing menu.**
4. Re-read `menus(first: 50)` and confirm the store matches [`menus.json`](../backup/2026-11-27/content/menus.json) again (5 menus, same item IDs).

Softer rollback that keeps the records: leave the menus in place (they are invisible while Craft is live), or fix a single item with `menuUpdate(id: <menu id>, title, handle, items)`, which replaces the whole item list, so send every item.
