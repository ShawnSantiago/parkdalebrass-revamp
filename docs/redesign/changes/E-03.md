## 1 · Why

- The new theme (unpublished, `gid://shopify/OnlineStoreTheme/196453663042`) already has `templates/page.our-story.json`, `page.why-brass.json`, `page.jewelry-care.json` and `page.size-guide.json` (read from the theme on 2026-11-27; their MD5 checksums match the repo files). The theme already links these handles: `templates/index.json` (hero link and story button → `/pages/our-story`, material button → `/pages/why-brass`), `page.our-story.json` → `/pages/why-brass`, `page.why-brass.json` → `/pages/jewelry-care`, `collection.json` (promo tile → `/pages/why-brass`, help strip → `/pages/size-guide` and `/pages/jewelry-care`) and the product page's Size guide popup (`product.json`, `page: size-guide`, also the `custom.size_guide` fallback in `04` §2). The planned `footer-learn` menu (E-04, `04` §3) links all four.
- `04` §3 and `phase-3-brief.md` §3.2 list exactly these four pages for Phase 3, created hidden.
- Creating them now, hidden, lets the four layouts be previewed with real page records in the unpublished theme's editor, and lets the owner review the draft copy in place, without anything reaching customers.
- AGENTS.md "Never invent facts": every fact not verified by the owner is a visible `[bracketed placeholder]`. The pages stay hidden while any bracket remains (`phase-3-brief.md` §3.3 "Done when").

### 1.1 · Template suffix set now (D-39; replaces the "default template" wording in `phase-3-brief.md` §2.1 and §3.2)

`phase-3-brief.md` §2.1 and §3.2 said to create the pages on the default template, because **Shopify Admin's** template list only shows the published (Craft) theme's templates. The Admin API has no such limit: `PageCreateInput.templateSuffix` takes any suffix. So each page is created with `templateSuffix` equal to its handle (`our-story` → `page.our-story`, and so on), as the E-03 task asks, and renders with its own template as soon as the new theme is published. Phase 5 step 5.3 becomes a check rather than an assignment. Recorded as D-39; both briefs now say so.

- Safe on the live Craft theme: Craft has no `page.our-story` (or the other three) template (its page templates are `page.json`, `page.contact.json`, `page.reviews.json` and `page.instant-LeMnKzmAHEXo1htp.json`, read 2026-11-27). Shopify falls back to the default page template for a missing suffix, and the pages are hidden anyway.
- Watch: if someone edits one of these pages in Admin **while Craft is live**, Admin's template select doesn't list the suffix and may reset it to the default on save. After any Admin edit before launch, re-read `templateSuffix`; Phase 5 step 5.3 checks it and restores it if needed.

## 4 · Rollback

The change is additive and the pages are hidden. Rolling it back fully means **deleting** them, so under D-28 **tell the owner before doing it**.

1. Read the four pages: `pages(first: 10, query: "handle:our-story OR handle:why-brass OR handle:jewelry-care OR handle:size-guide")`, selecting `id handle isPublished templateSuffix updatedAt`. Use the IDs in §5.
2. If one was made visible, hide it first with `pageUpdate(id: <page id>, page: { isPublished: false })`.
3. If menus (E-04) or theme settings already link to a handle, repoint or remove those links first, or the links will 404 once the theme is live.
4. Delete with `pageDelete(id: <page id>)`.
5. Re-read `pagesCount` and the handles and confirm the store matches [`pages.json`](../backup/2026-11-27/content/pages.json) again (16 pages; `fathers-day-24`'s visibility is outside E-03, see §2).

Softer rollbacks that keep the records: leave them hidden (they already are), or clear the template suffix with `pageUpdate(id: <page id>, page: { templateSuffix: "" })` so they use the default `page` template.
