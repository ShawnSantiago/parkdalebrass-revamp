## 1 · Why

- The new theme already reads all nine `04` §2 product keys (`snippets/pb-product-detail.liquid`, `snippets/pb-product-card.liquid`, `sections/pb-featured.liquid`, `sections/related-products.liquid`, `sections/main-product.liquid`) and `custom.category_line` on collections (`sections/pb-collection-header.liquid`). Every block hides when its field is empty (D-09).
- With definitions in place, the owner can enter verified facts in Admin, and the E-05 product CSV import (`product-data/`) maps onto typed fields instead of creating unstructured metafields.
- Types follow `04` §2, with `dimensions` and `care_instructions` as multi-line text (D-18). `category_line` is single-line text (D-37).
- Each description states the integrity rule for that field (AGENTS.md "Never invent facts"; banned claims in `04` §1), so whoever fills it in sees the rule in Admin.

## 2 · Pre-checks (2026-11-27, before applying)

- **Reuse check:** a fresh read of `metafieldDefinitions` (PRODUCT: 14 definitions, COLLECTION: 0, one page each, `hasNextPage` false) matches the backup exactly. No `custom.*` definition exists for either owner type, and no existing definition is compatible with any planned key (see the backup's `collisionCheck`: `global.description_tag` is an SEO field, `whatnot.whatnot_description` is a channel override). **Nothing to reuse; nothing with the same namespace and key but a different type.**
- **Unstructured values:** a fresh read of `metafields(namespace: "custom")` on all 14 products and all 14 collections returned none, so creating the definitions converts no existing data.
- **Storefront access:** Liquid reads metafields whatever the definition's Storefront API setting is (shopify.dev, "About metafields": "This setting doesn't affect Liquid templates"). The theme makes no Storefront API calls for metafields, so `access.storefront` is set to **`NONE`**. Admin access needs no setting for a merchant-owned namespace.
- **Pinning:** Admin only shows pinned definitions on a product or collection page by default (`metafieldDefinitionUnpin` description), so all ten are pinned so the owner can fill them in. The product owner type has 8 pinned definitions now (all `whatnot.*`); 8 + 9 = 17. Pinning is Admin UI only.
- **No validations or capabilities.** `04` §2 defines none, and adding limits (choices, lengths) would be inventing product rules. Smart-collection, filter and analytics capabilities stay off: E-02 collections use tag and product type, and E-06 filters are Availability and Price only.

## 3 · The exact change

Ten `metafieldDefinitionCreate` calls, namespace `custom`, `access: { storefront: NONE }`, `pin: true`, no validations, no capabilities.

| # | Owner type | Key | Type | Name | Description (as stored) |
| --- | --- | --- | --- | --- | --- |
| 1 | PRODUCT | `short_description` | `multi_line_text_field` | Short description | One or two sentences under the price, and the card fallback. Owner-verified facts only; none of the banned claims in 04 §1 without evidence. Empty hides it. |
| 2 | PRODUCT | `material` | `single_line_text_field` | Material | Base metal and any coating or plating, as the supplier documents it. Owner-verified only. No solid brass, nickel-free, lead-free or hypoallergenic without evidence. Empty hides it. |
| 3 | PRODUCT | `finish` | `single_line_text_field` | Finish | The finish this product is actually sold in (e.g. Brushed). Owner-verified only. If the finish changes the SKU, use the Finish option instead (D-09). Empty hides it. |
| 4 | PRODUCT | `patina_notes` | `multi_line_text_field` | Patina notes | How this finish changes with wear, as seen on samples. Leave empty for coated or plated finishes that don't patina. Never tarnish-proof or skin-safe. Empty hides it. |
| 5 | PRODUCT | `dimensions` | `multi_line_text_field` | Dimensions | Measured dimensions, one per line, in cm/mm and inches. Only owner-measured values; never estimated. Plain multi-line text (D-18). Empty hides it. |
| 6 | PRODUCT | `fit_notes` | `multi_line_text_field` | Fit notes | Measured fit, shown under the size picker (e.g. inner circumference, opening). Owner-verified only. No 'adjustable' without tested limits. Empty hides it. |
| 7 | PRODUCT | `care_instructions` | `multi_line_text_field` | Care instructions | Care steps confirmed on samples for this finish. No abrasive polish, acid or soaking advice for coated pieces without supplier approval. Multi-line text (D-18). Empty hides it. |
| 8 | PRODUCT | `origin` | `single_line_text_field` | Origin | Only owner-verified origin, with evidence on file. Never inferred from the Toronto brand location. Enter the place only; the theme shows 'Made in …'. Empty hides it. |
| 9 | PRODUCT | `size_guide` | `page_reference` | Size guide page | Optional page that replaces the size-guide popup for this product. The page must hold only measured, validated sizes. Empty uses the global size-guide page. |
| 10 | COLLECTION | `category_line` | `single_line_text_field` | Category line | Optional line under the collection title (e.g. CUFFS · CHAINS · PENDANTS). Name only categories with published products. Overrides the menu-built line (D-37). Empty uses the menu. |

Mutation used for each row (values passed as variables):

```graphql

    userErrors { field message code }
  }
}
```

```json
{ "definition": { "ownerType": "PRODUCT", "namespace": "custom", "key": "<key>", "type": "<type>",
  "name": "<name>", "description": "<description>", "access": { "storefront": "NONE" }, "pin": true } }
```

Not changed: no product, collection, page or menu; no value on any record; no existing definition (`reviews.*`, `whatnot.*`, `shopify--discovery--*` untouched); nothing published or unpublished.

## 4 · Rollback

The change is additive and holds no data until someone fills a field. Rolling it back means **deleting** definitions, so under D-28 **tell the owner before doing it**.

1. List what exists now: `metafieldDefinitions(ownerType: PRODUCT, namespace: "custom")` and `metafieldDefinitions(ownerType: COLLECTION, namespace: "custom")`, selecting `id key metafieldsCount`.
2. If any definition has `metafieldsCount` > 0, export those values first (product or collection handle, key, value) to `docs/redesign/backup/<date>/` and keep them. Don't delete owner-entered facts without the owner's say.
3. To only tidy Admin, unpin instead of deleting: `metafieldDefinitionUnpin(identifier: { ownerType: PRODUCT, namespace: "custom", key: "<key>" })`.
4. To remove a definition: `metafieldDefinitionDelete(identifier: { ownerType: <PRODUCT|COLLECTION>, namespace: "custom", key: "<key>" }, deleteAllAssociatedMetafields: false)`. With `false`, any values stay on the records as unstructured metafields, so nothing the owner entered is lost.
5. Re-read both lists and confirm they match the backup (14 PRODUCT definitions, 0 COLLECTION).

The theme needs no rollback: with the definitions gone, `product.metafields.custom.*` reads empty and every block hides, as it does today.

### Verification

- **Admin (re-read after applying):** PRODUCT now has 23 definitions (the 14 from the backup plus the nine above), COLLECTION has 1; `hasNextPage` false on both. Each new definition has the namespace, key, type, name and description in §3, `access.storefront: NONE`, no validations, `adminFilterable` and `smartCollectionCondition` off, `metafieldsCount: 0` and `validationStatus: ALL_VALID`.
- **Existing definitions unchanged:** the 14 pre-existing PRODUCT definitions read back with the same IDs, types, storefront access, pinned positions (the `whatnot.*` pins 1, 1, 2, 2, 2, 5, 6, 8) and value counts (`reviews.rating` 2, `reviews.rating_count` 2, the three recommendation fields 2 each, the rest 0) as the backup.
- **Live storefront (GET only, live Craft theme):** `/`, `/collections/metal-smoking-pipes` and `/products/brockton-mk2` return 200, with no field names or keys from this change in the HTML. `/products/the-brockton` returns its existing 301 to `/products/brockton-mk2`. Craft references no metafields (`craft-audit.md`), and no record holds a value, so nothing customer-facing changed.
- **Unpublished preview (theme 196453663042):** `/products/brockton-mk2` renders on the Archive theme with no `pb-specs`, short-description or fit-note output, and `/collections/metal-smoking-pipes` renders its header with no category line. This matches empty fields hiding their blocks (D-09).

### Notes for later

- The fields stay empty until owner-verified facts arrive (C-02 to C-06) and E-05 imports them. Don't fill them from legacy pipe copy (`craft-audit.md`: pipe dimensions are hard-coded in Craft sections and must not migrate).
- Storefront API access is off. Turn it on (`metafieldDefinitionUpdate`, `access.storefront: PUBLIC_READ`) only if something outside Liquid needs these fields, such as a headless storefront or an app that reads them through the Storefront API. Liquid doesn't need it.
- `reviews.rating` and `reviews.rating_count` remain legacy pipe-review aggregates; the theme must never read them (D-13).
